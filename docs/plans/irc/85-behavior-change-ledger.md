## How to read the tables

Bottom line: each row is one behavior change merged across reports; its id is stable and other notes cite it.

- What existed: the surface: native tables API, House Tables, Spark SQL through the existing catalog, a maintenance job,
  the Java client, a shipped artifact, the build, a CI workflow.
- Line: which build line shows the change, and how that is known. "Both" means the changed file is compiled on both
  lines and nothing in it checks the line. Code under `services/tables/src/iceberg-1.12` compiles only on the default
  line (`services/tables/build.gradle:104-121`, BD B26); everything else in `services/`, `iceberg/openhouse/`,
  `integrations/spark/spark-3.5/`, `apps/spark-3.5/` and `libs/` is compiled on both lines.
- Size: SMALL (one agent, one pull request, under about 2,000 lines and 20 files) or FOUNDATION, with what undoing it
  would invalidate.
- Disposition: RESTORE (put main's behavior back), GATE (keep the new behavior behind a property whose default
  reproduces main), KEEP-FIX (it fixes a real defect on main: keep it, write its justification in the code and the merge
  record, and offer it upstream as its own small change), KEEP-DIRECTED (the owner directed it), OWNER (needs the owner;
  the exact question is in the row).
- "Ready" in a disposition means the orchestrator has already decided it (three items, listed in
  `86-review-findings-and-fix-forward.md`).
