# Apache Iceberg's REST compatibility kit (RCK) against the tables service: every kit test, its
# outcome at each configuration the kit runs at, and for each test that does not pass the cause it
# fails or is skipped for. The one reviewed place for "expected to fail". restCompatKitTest (the
# default configuration) and restCompatKitFormatV3Test (format v3 tables enabled) each pass exactly
# when every test the kit runs is listed here, every listed test runs, and each has the outcome and
# cause listed. How to read and change this file: docs/development/iceberg-fork.md ("Apache
# Iceberg's REST compatibility kit").
#
# Lines:
#   category <NAME> | <class> | <reason>          a cause, defined above the first test listed under it
#   <test> | PASSED
#   <test> | FAILED or SKIPPED | <NAME> | <throwable type> | <message prefix>
# <test> is <suite class>.<test name as Gradle reports it>. A line holds at both configurations,
# unless it starts with "default: " or "v3: "; a test listed that way is listed once for each.
# For a test that fails, the throwable is the one that ended it: its first failing assertion
# (java.lang.AssertionError, or org.opentest4j.AssertionFailedError from some AssertJ assertions,
# its message naming what the client answered), or an exception the client threw outside an
# assertion. For a skip, it is the kit's assumption that did not hold
# (org.opentest4j.TestAbortedException), or "disabled" and the reason the kit disabled it. The
# message must start with the prefix, compared with all whitespace as single spaces; " ... " in a
# prefix stands for any text. A prefix holds only what is stable from run to run: no paths, UUIDs,
# ports or times.
#
# The number of tests under each cause is printed by each green run; it is not kept here.
#
# Classes (each test is filed under the first step it fails at; a later step may fail for another
# reason once that one is gone):
#   a  OpenHouse model difference the kit has a capability flag for: the flag is set (see
#      OpenHouseRestCompatibilityKit*Tests) and the test is skipped by the kit's own assumption
#   b  OpenHouse model difference the kit has no flag for
#   c  a route or feature the server does not serve yet
#   d  a defect: the server breaks the spec on a route it serves
#   e  a kit or client assumption that holds only for Iceberg's reference implementation
